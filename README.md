# GuardSense Fit System 2 — Real-Only Binary Repository

This is the **separate real-data-only binary** repository for GuardSense Fit System 2.

- **Repository mode**: `real_only_binary`
- **Current labels**:
  - `0 = normal / non-fight`
  - `1 = fight`
- **Primary goal**: train and evaluate Trigger (pose) and Verifier (video) using currently collected **real datasets only**.
- **Not part of this repo's training flow**: Simuletic/synthetic dependency.

## How this differs from the synthetic-ready 3-class repo

This repo is intentionally scoped for binary real-data training now, while keeping architecture/configs compatible with later 3-class fine-tuning. The original synthetic-ready repository remains separate and untouched.

## End-to-end binary workflow (recommended)

1. **Extract pose from real videos** for Trigger.
2. **Prepare Trigger dataset** (`.npy`, `.hdf5`, metadata, split manifest).
3. **Train Trigger** (binary).
4. **Prepare Verifier dataset** (standardized `.mp4` clips + manifests/reports).
5. **Train Verifier** (binary).
6. **Evaluate Trigger/Verifier**.

### One-command real-only binary orchestration (new)

Use the dedicated orchestration runner for local development/training:

```bash
python src/scripts/run_real_only_pipeline.py --all
```

Quick variants:

```bash
# Trigger-only pipeline (extract -> prepare -> train -> eval)
python src/scripts/run_real_only_pipeline.py --trigger-only

# Verifier-only pipeline (prepare -> train -> eval)
python src/scripts/run_real_only_pipeline.py --verifier-only

# Preview commands only (no execution)
python src/scripts/run_real_only_pipeline.py --all --dry-run

# Skip stages conservatively when outputs/checkpoints already exist
python src/scripts/run_real_only_pipeline.py --all --skip-existing
```

Config overrides are supported for each stage:

```bash
python src/scripts/run_real_only_pipeline.py --all \
  --pose-config configs/pose_extraction.yaml \
  --trigger-data-config configs/trigger_data.yaml \
  --trigger-train-config configs/trigger_train.yaml \
  --trigger-eval-config configs/trigger_eval.yaml \
  --verifier-data-config configs/verifier_data.yaml \
  --verifier-train-config configs/verifier_train.yaml \
  --verifier-eval-config configs/verifier_eval.yaml
```

Notes:
- The runner calls existing per-stage scripts (no replacement of core training/prep logic).
- `--skip-existing` uses conservative checks (manifest/dataset/checkpoint presence) to avoid accidental re-runs.
- The long manual commands below are still supported and recommended for stage-level debugging.

### Canonical commands (start to finish)

```bash
# 1) Pose extraction (real videos -> pose txt)
python src/scripts/extract_pose_from_videos.py --config configs/pose_extraction.yaml

# 2) Trigger preprocessing (.npy/.hdf5/manifests)
python src/scripts/prepare_trigger_data.py --config configs/trigger_data.yaml

# 3) Trigger training (binary)
python src/scripts/train_trigger.py --config configs/trigger_train.yaml

# 4) Trigger evaluation
python src/scripts/eval_trigger.py --config configs/trigger_eval.yaml

# 5) Verifier preprocessing (clip standardization + manifests)
python src/scripts/prepare_verifier_data.py --config configs/verifier_data.yaml

# 6) Verifier training (binary)
python src/scripts/train_verifier.py --config configs/verifier_train.yaml

# 7) Verifier evaluation
python src/scripts/eval_verifier.py --config configs/verifier_eval.yaml
```

### Optional orchestrated run

`run_full_pipeline` can execute the same sequence from one config (`configs/runtime.yaml`), including pose extraction by default:

```bash
python src/scripts/run_full_pipeline.py --config configs/runtime.yaml --output-dir artifacts/full_pipeline
```

Use `--dry-run` to preview commands.

## Trigger specifics (unchanged core assumptions)

- Inputs: extracted pose `.txt` -> preprocessing exports `.npy` and `.hdf5`
- Final tensor shape: `(B, T, K, C)`
- Defaults: `T=32`, `K=17`, `C=3 (x, y, visibility/confidence)`
- Windowing: 32-frame windows, 50% overlap
- Normalization and visibility handling are preserved in preprocessing

## Verifier specifics (unchanged core assumptions)

- Inputs: `.mp4` / `.avi`
- Preprocessing targets: 30 FPS, 640x360 (or compatible), 2–4 seconds
- Outputs: standardized clips + metadata + split manifest + rejections + dataset report

## Checkpoint/output convention

- Trigger run dirs: `artifacts/runs/trigger_binary_real_only_<architecture>_<timestamp>/`
- Verifier run dirs: `artifacts/verifier_runs/verifier_binary_real_only_<backbone>_<timestamp>/`
- Both trainers still update `latest/` alias under their output roots.
- Eval scripts still accept explicit paths, `latest/` aliases, and fallback to newest valid checkpoint automatically.

## Runtime/Fusion status in this repo

Runtime/fusion code is preserved for deployment/experimentation, but it is **optional** here. Binary training/evaluation does **not** require Frigate/runtime stages.

## Future 3-class upgrade path (documented, not implemented here)

This repo remains compatible with later expansion to:

- `0 = normal`
- `1 = pre-fight`
- `2 = fight`

Recommended future path:
1. Train binary models in this repo.
2. In 3-class repo, load binary-trained backbone weights.
3. Replace/expand final classification layer to 3 logits.
4. Fine-tune on 3-class data.

`num_classes`, label maps, and metrics are config/model driven to support this migration.
